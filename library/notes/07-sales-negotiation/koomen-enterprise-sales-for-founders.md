# Enterprise Sales for Founders（创始人的企业销售课）

> 来源说明：YC Startup Library 免费视频，页面附完整逐字稿，已转文本存私有目录。视频约 22 分钟，章节时间戳：Intro 0:00、Prospecting 3:29、Outreach 5:15、Qualification 10:09、Pricing 15:00、Closing 18:13、Procurement 18:58、Implement 20:02。下文用这些章节定位。

## 一句话

在找到 product-market fit 之前，**销售是创始人的工作，没法外包**。它不是心理战，而是"深入理解客户的问题并帮他解决"。按漏斗走：**假设 → 找人 → 触达 → 资格判断（多问少讲）→ 讲故事式演示 → 敢报高价 → 不被采购流程意外打断 → 把落地当成自己的项目**。

## 核心论点

1. **你能卖，而且只有你能卖**（Intro）："如果你自己卖不出去，大概率也雇不到人替你卖"，因为 PMF 之前的销售是"创业性质的"：需要愿景、在客户面前的可信度、大量试验，以及和产品的紧密反馈回路。技术型创始人有两大优势：**专业性**（既懂问题也懂产品）和**信念**（真心相信能解决客户的问题）。"Sales isn't about tricking people."
2. **先有销售假设，再找客户**（Prospecting）：句式是"客户 X 有问题 Y，我们的产品帮他解决"。Optimizely 早期的假设："中小型科技、媒体、电商公司的营销人员想在网站上做 A/B 测试，但现成工具要求写代码；Optimizely 让他们不用写代码就能测试。"然后用 BuiltWith 筛选那些用了分析工具和 JS 框架的公司（说明对方在乎网站、技术较成熟），再用 Apollo、LinkedIn Sales Navigator 找到具体的人。
3. **最好的触达是让客户来找你**（Outreach）：持续发布、做技术内容、做可以分享的自助 demo、在客户聚集的论坛里当专家，客户去行业会议你也要去，并提前约好会面。其次是**暖介绍**（找共同联系人）。冷邮件效率最低，但做对了也有效：逐封手写、短、请求明确、说明"为什么是你"。**经验法则：只发你自己收到会兴奋的邮件。**
4. **反模式：只和"好说话的人"聊**（Outreach 后半）：这会筛选出容易交谈的人，而不是好客户。给你很多"友情反馈"，制造进展的假象。两种典型表现：① 把只有大公司才有的问题（如 HR 信息系统）卖给创业公司；② 需要自上而下采用的产品（如医院软件，需要 CIO、IT、医生、运营协同）却去找一线个人。YC 的真实意思不是"卖给买得快的人，不管他是不是好客户"，而是**找到有问题、有预算、有决策权的人**。
5. **第一次通话不是推销，是资格判断**（Qualification）：只做两件事：① 判断对方是否有这个问题、有没有预算和决策权；② 约下一次演示。最大的错误是"问得太少"，一上来就推销。销售不是对抗，你面对的是一个具体的人，好销售大部分时间在听。问题清单："什么让你决定接这通电话？讲讲这个问题。有多久了？多严重？还影响谁？怎么量化影响？为什么还没解决？预算多少？你们怎么采购软件？谁拍板？还有谁要参与？"发现对方不合适也是好结果：省了双方的时间。
6. **演示是讲一个好故事，不是功能巡游**（Qualification 后半）：开头复述"主角"（用户）和她的问题，展示你在第一次通话里听得多认真；然后讲主角怎么解决问题，每个功能都有出场理由，最好有"魔法时刻"；尽量个性化（用对方的 logo、网站、客户名、同事名）。Optimizely 早期花了几周做了一个能直接在客户自己网站上演示的功能，看到营销人员"眼睛亮了"。
7. **定价：大胆报，当作实验**（Pricing）：没有公式。提前问"这个问题让你们花了多少钱？多少人在维护内部方案？预算多少？在竞品上花多少？"。企业版不公开价格，可以每次试一个价格。**最常见的错误是要价太低，甚至免费换反馈**。真正想要的客户很难被高价吓跑。高价还能帮你筛选出最迫切的客户，"让客户更认真"。要给对方准备一页纸，因为"最重要的定价讨论发生在你不在场的时候"。早期"为学习而优化，而不是为单位经济"。
8. **成交是一串事，不是一次谈话**（Closing / Procurement）：大公司有安全审查、隐私审查、法务、合规。最大的错误是**被意外打断**，以为成交了，其实还要几周甚至黄掉。解法还是**多问**：提前问清采购流程和签字人；能并行的（安全问卷）先开始；法律文件尽量简单（推荐 YC 公司 Common Paper 的开源模板）；时间表和工作范围放进订单或共享项目文档，不放进合同；你的对接人此时已经是你的**内部拥护者**，卡住时先找他。
9. **落地是你的责任**（Implement）：Optimizely 签过六位数的单，一年后续约时发现客户**一次 A/B 测试都没跑**。表面原因是买软件的营销团队说服不了工程团队帮忙安装；真正原因是"我们没做好自己的工作"：客户买的是解决方案，不是产品。改进：在销售过程早期就问实施需要什么工作，签约前和营销、工程负责人一起做详细实施计划，做不到就不签；把客户实施当作自己公司的高优先级项目来管理（共享路线图、每项任务有负责人、定期检查）。"销售漏斗只有在客户习惯性使用你的产品时才真正结束。"

## 框架 / 模型

### A. 创始人销售漏斗（每一步的产出和头号错误）

| 步骤 | 产出 | 头号错误 |
|---|---|---|
| 假设 | "客户 X 有问题 Y，我们帮他解决" | 没有假设，谁都聊 |
| 找客户 | 公司列表 + 具体的人 | 只找好说话的人 |
| 触达 | 约到第一次通话 | 群发模板邮件 |
| 资格判断 | 有问题？有预算？有决策权？+ 约演示 | 一上来就推销，问得太少 |
| 演示 | 对方确信你能解决他的问题 | 功能巡游、不个性化 |
| 定价 | 一个让你有点不舒服的数字 + 一页纸 | 要价太低或免费 |
| 成交 | 签字 | 被采购流程意外打断 |
| 落地 | 客户习惯性使用 | 以为落地是客户的事 |

### B. 资格判断问题清单（可直接打印）

1. 什么让你决定接这通电话？
2. 讲讲这个问题：多久了？多严重？还影响谁？
3. 你们怎么量化它的影响？
4. 为什么还没解决？
5. 预算多少？
6. 你们怎么采购？谁拍板？还有谁要参与？

### C. 冷邮件检验

- 是不是手写的？能不能看出"为什么是你"？
- 请求是否明确、只有一个？
- 我自己收到会兴奋吗？

## 案例与数据

- **Optimizely**：Koomen 和联合创始人 Dan（Siroker）都是技术背景，靠试错学会了销售，公司做到 1 亿美元 ARR（页面简介）。
- **5 倍报价**：Dan 鼓起勇气报了 **$10,000/月**，客户砍到 **$2,000/月**后成交。"我们的初始报价是对方愿付价格的 5 倍，他们照样买了。"
- **Stripe**：Collison 兄弟早期定价比竞争对手更高，照样卖得出去，这本身就证明他们抓对了需求，也让他们专注于最迫切的客户。
- **医院 vs Notion**：自下而上采用的工具（Notion）可以找个人或团队经理；需要多部门协同的医院软件，必须找 CFO 或 CIO。
- **六位数的单、一次测试都没跑**：落地失败的教训（见核心论点 9）。
- **推荐读物**：Pete Kazanjy《Founding Sales》，网上免费（逐字稿里误写作 "Peter Kazey"）。

## 适用边界与常见误用

1. **面向 B2B 企业软件**：Koomen 自己说内容对任何刚开始做销售的创始人"都应该广泛有用"，但定价、采购、落地部分主要针对企业客户。对 C 端或学生个人服务，要把"采购流程"翻译成"对方要征求谁的同意"（家长、导师、合伙人）。
2. **"报高价"有前提**：前提是对方**真的需要**，并且你已经在资格判断和演示中建立了价值。在没有资格判断时报高价，只会被直接拒绝。
3. **"多问"≠"审讯"**：问题要服务于判断"是否合适"和"怎么帮"。连接 SPIN：背景信息尽量提前查，现场多问难点和影响。
4. **反模式提醒对学生特别重要**：学生最容易只找同学、朋友聊（好说话），得到友情反馈。这是 01 模块 Mom Test 和本课共同警告的。
5. **工具时效性**：Apollo、Sales Navigator、Common Paper 是 2024 年的工具推荐，可能会变；底层逻辑不变。

## 出题素材

1. **Oliver 真实场景，写销售假设**：用"客户 X 有问题 Y，research-crawler 帮他解决"的句式写 3 个候选假设（例如：做竞品分析的学生咨询社团、跨境电商卖家、写行业 newsletter 的人）。按"有问题 / 有预算 / 有决策权"给每个打分，选一个，写出用来筛选目标的两个"信号"（类似 Optimizely 用 BuiltWith 的思路）。
2. **冷邮件改写**：Oliver 的初稿是"Hi，我开发了一个调研抓取工具，功能很强大，有兴趣试试吗？"按 Koomen 的标准指出 3 个问题，并给出一个 ≤80 字的改写版。
3. **资格判断角色扮演**：导师扮演一个"很好聊、很热情，但没预算也不拍板"的学生社团负责人。Oliver 要在 10 分钟内识别出来，并礼貌结束或转向真正的决策人。
4. **定价实验设计**：为"定制调研报告"设计一个三次报价的实验（三位不同客户），写出每次报价前要问的 3 个问题，以及根据什么反应来调整价格。追问：Koomen 说"为学习而优化，而不是为单位经济"，这个原则什么时候应该停止？
5. **落地责任**：假设一个客户付了钱，但两周都没用你交付的数据。按 Koomen 的方法写一份"落地计划"（共享路线图、负责人、检查节奏），并说明下次应该在销售流程的哪一步就把这件事谈清楚。
