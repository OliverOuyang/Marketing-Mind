# How to Get Startup Ideas（如何获得创业点子）

> 来源说明：Paul Graham 个人网站免费全文，已转文本存私有目录。原文分节：Problems / Well / Self / Noticing / School / Competition / Filters / Recipes / Organic，外加 17 条注释。下文用这些小标题定位。

## 一句话

好点子不是"想出来"的，是"**注意到**"的。**活在未来，然后做出缺失的东西**（Live in the future, then build what's missing）：先让自己站到一个快速变化领域的前沿，再关掉"不够性感""太麻烦""会不会成大公司"这些过滤器，看见那些显而易见、却还没人做的问题。

## 核心论点

1. **从问题出发，最好是自己的问题**（开头、Problems）：最好的创业点子有三个共同点：创始人自己想要、自己能做出来、很少有人意识到值得做。微软、苹果、雅虎、谷歌、Facebook 都是这样开始的。创业公司最常见的错误是"解决没人有的问题"。Graham 自己 1995 年想把画廊搬上网，6 个月后才发现画廊根本不想上网。
2. **警惕"编出来的"点子**（Problems）：YC 称之为"情景剧式"点子，例如"宠物主人社交网络"。它听起来合理，问养宠物的朋友，他们会说"嗯，也许我会用"，而不是"我绝不会用"。"把这种反应加总到全体人口上，你得到的是零个用户。"（参见注释 [2]：如果你对一个点子只知道"它听起来合理"，就要假设它是坏点子。）
3. **要深井，不要浅坑**（Well）：想象一个图，x 轴是所有可能想要你东西的人，y 轴是他们有多想要。早期只能挖小洞，你可以挖**又宽又浅**的（很多人有一点想要），也可以挖**又窄又深**的井（少数人非常想要）。**选后者**。Altair Basic 只有几千个 Altair 用户，但没有它，他们只能写机器语言；Facebook 一开始只给几千个哈佛学生用，但他们非常想要。检验问题："**谁现在就想要这个？谁想要到愿意用一个两人小公司做的、很烂的第一版？**"答不出来，点子多半不好。
4. **井还要有出路**（Well 后半）：只对哈佛学生有用的东西不是好点子。Facebook 好在大学都很相似，在哈佛能用，在任何大学都能用；有了所有大学生，放开注册就能得到其他所有人。微软的路径：Altair 上的 Basic → 其他机器上的 Basic → 其他语言 → 操作系统 → 应用 → 上市。但出路往往**事先看不出来**，Airbnb 最初只想让人在开会期间出租地板空间。
5. **成为会有好点子的人**（Self）：引 Robert Pirsig："想画一幅完美的画？很简单。让自己变完美，然后自然地画。"站在快速变化领域的前沿（作为创造者或**作为用户**都行），你的直觉更可能对。Zuckerberg 觉得 Facebook 是好点子，与其说因为他是程序员，不如说因为他"已经活在网上"。引 Paul Buchheit：前沿的人"活在未来"。成功创始人的点子通常是"外部刺激撞上有准备的头脑"：Gates 和 Allen 听说了 Altair，Drew Houston 忘带 U 盘。应该用的动词不是"想出"，而是"**注意到**"，YC 称之为"有机的"（organic）点子。
6. **怎么注意到**（Noticing）：关掉所有过滤器，只开"缺了什么"这一个；尤其先关掉"这能成大公司吗？"（以后再用）。最强的过滤器是**把现状视为理所当然**。要质疑日常：你的收件箱为什么爆满？**特别留意让你烦躁的事**："当某件事让你烦，可能是因为你活在未来。"好的问题对你来说应该显而易见：Viaweb 做网店时，网店都是设计师手写 HTML，对程序员来说"显然应该由软件生成"。建议在后台开一个"第二自我"，记录缺口和异常；注释 [6] 建议每晚写日记，只记当天注意到的缺口和异常，不记点子。被称为"**玩具**"的东西往往是好点子：它有一个点子需要的一切，除了"重要"。
7. **大学生该做什么**（School）：不要去上"创业课"，而是把自己"推进未来"；跨领域最容易发现问题（CS 学生去学遗传学，或者去生物科技公司暑期打工）；或者干脆不上额外的课，**直接做东西**，最好和其他同学一起做，得到"有机的点子 + 有机的创始团队"。微软和 Facebook 都是在哈佛 1 月的复习周（Reading Period）起步的。注意"研究"：本科生写了个东西朋友都在用，很可能是好点子；博士论文则极不可能。
8. **竞争**（Competition）：好点子看起来显而易见，所以你会觉得"来晚了"，这反而是好点子的迹象。花十分钟搜索就能确认。创业公司被竞争对手杀死"极其罕见"，除非对手有让用户无法选择你的锁定效应。拥挤的市场其实是好信号（有需求，现有方案都不够好），只要你有一个关于"大家都忽略了什么"的论点，最好是"他们没有贯彻自己洞察的勇气"（谷歌就是这样）。
9. **两个最危险的过滤器**（Filters）：**麻烦过滤器**（schlep filter，害怕繁琐的事）和**不性感过滤器**（unsexy filter，讨厌的领域）。Stripe 是关掉麻烦过滤器的典范：几千个程序员都知道支付处理很痛苦，但都本能地回避，于是 Stripe 获客很顺。关掉麻烦过滤器比关掉不性感过滤器更重要，因为前者更可能是错觉。
10. **需要马上有点子时的"食谱"**（Recipes，Plan B）：
    - 只在**你有专业判断力**的领域找（数据库专家别去做青少年聊天软件，除非你也是青少年）；
    - 从**你需要的东西**找起；回想上一份工作里有没有人说过"为什么没人做 X？有人做我立刻就买"；
    - 找**你有什么不同于常人的地方**，最好是越来越多人会变成的那种不同；**年轻**本身就是一种不同（23 岁以下：你和朋友想做而现有技术做不到的是什么？）；
    - 去聊别人的缺口：什么缺失？什么繁琐、烦人？像顾问一样只为一个用户解决问题；Rajat Suri 为了给餐厅做软件，自己去当了服务员；
    - **主动去找不性感、有麻烦的点子**："别试图做 Twitter……做点人们愿意付钱的不性感的东西"；问自己"你现在愿意为什么付钱？"；
    - 找**正在死去（或者该死）的行业**，想象未来人们会说"这个取代了 X"，而且取代往往"从侧面进来"；
    - 找被大玩家忽视的"邋遢但老练"的用户群（像早期的微电脑"爱好者"）；
    - 找**浪潮**（比如基因测序、3D 打印的成本像摩尔定律一样下降）。
    但这些都是"模拟有机方法"的 Plan B："如果你就在快速变化领域的前沿，你不用找浪潮，你就是浪潮。"

## 框架 / 模型

### A. 井型检验（Well Test）

| 问题 | 好的回答 |
|---|---|
| 谁**现在**就想要？ | 能点名一个具体人群（甚至具体的人） |
| 想要到什么程度？ | 愿意忍受一个很烂的第一版 |
| 这个井有出路吗？ | 相似的相邻人群可以快速扩展 |
| 我是不是那个人群的一员，或者离他们很近？ | 是（创始人即用户最好） |

### B. 过滤器清单（关掉 → 再打开）

| 过滤器 | 何时关 | 何时开 |
|---|---|---|
| "这能成大公司吗？" | 发现阶段 | 筛选阶段 |
| 现状理所当然 | 始终尽量关 | — |
| 麻烦（schlep） | 发现阶段（它多半是错觉） | 评估真实执行成本时 |
| 不性感 | 发现阶段 | 评估能否长期投入热情时（可以部分保留） |
| "我来晚了" | 始终关，花 10 分钟搜一下就够 | 发现对手有锁定效应时 |

### C. 有机方法 vs 食谱方法

```
有机（Plan A）：活在未来 → 做你觉得有趣的东西 → 注意到缺失 → 点子自己出现
食谱（Plan B）：在你有判断力的领域 → 从你/别人的需要、你的不同、死去的行业、被忽视的用户、浪潮里找
共同纪律：用"谁现在就想要？"来过滤
```

### D. 缺口日记（注释 [6]）

每晚 2 分钟，只记当天注意到的"缺口和异常"（不记点子）。这和 08 模块练习 1"信号日记"是同一个习惯。

## 案例与数据

（均出自原文。）

- **Graham 的画廊网站**（1995）：画廊不想上网，浪费 6 个月（Problems）。
- **宠物主人社交网络**：编出来的点子的标准反例（Problems）。
- **Altair Basic、Facebook**：深井的标准正例（Well）。
- **Airbnb**：起初只想在会议期间出租地板空间，没预见到后来的扩张（Self）。
- **Drew Houston**：忘带 U 盘 → Dropbox；之前做过一个不太好的 SAT 备考创业（Self、Noticing）。
- **Viaweb**：网店应该由软件生成，对程序员来说显而易见（Noticing）。
- **Stripe**：关掉麻烦过滤器（Filters）。
- **Hotmail**：创始人起初写它，是为了在上班时讨论他们之前的创业点子（Recipes，注释 [15]）。
- **Rajat Suri（E la Carte）**：为了给餐厅做软件去当服务员（Recipes）。
- **Wozniak 与 HP**：Apple I 用电视当显示器，HP 觉得"太掉价"所以拒绝了；用电视是因为 Wozniak 自己买不起显示器，在解决自己的问题（Recipes，注释 [17]）。
- **注释 [15]**（Paul Buchheit）：让有坏点子的公司"尽快去卖产品（在浪费时间做出来之前）"，他们不仅会发现没人要，还常常在推销坏点子的过程中发现真正的点子。
- **注释 [14]**："Would you use this thing yourself, if you hadn't written it?"（如果不是你写的，你自己会用吗？）"你会惊讶答案为'不'的次数之多。"

## 适用边界与常见误用

1. **"自己的问题"可能只是个人怪癖**：要配合井型检验，确认还有一群人"非常想要"，并且有出路。
2. **"活在未来"需要时间**：Graham 说这是"最坏情况下要一年而不是一个周末"的食谱。想一周内想出好点子的学生，只能用食谱法，而且必须更严格地过滤。
3. **"竞争不重要"有前提**：没有锁定效应、你有"大家都忽略了什么"的具体论点，而不只是"做一个不烂的 X"。
4. **偏软件和技术**：Graham 自己说学编程"不是必要的，但在可预见的未来是充分的"。对非技术背景的学生，"前沿"可以是一个快速变化的用户领域（新平台、新工具的重度用户）。
5. **和 Drucker 的关系**：Graham 的"注意到让你烦的事"对应 Drucker 的"流程需要"和"不协调"；"浪潮"对应"新知识""产业结构变化"。可以用 Drucker 的七个来源给 Graham 的观察做分类。
6. **和 Mom Test 的关系**："问朋友会不会用"得到的"也许会"是假信号（宠物社交网络），这与 01 模块的 Mom Test 一致：问过去的具体行为，而不是对未来的假设。

## 出题素材

1. **Oliver 真实场景，深井检验**：research-crawler 的潜在用户里，谁"现在就想要、愿意用一个很烂的第一版"？点名 3 类人（最好能点名具体的人），并说出这口井的出路。如果答不出来，说明什么？
2. **缺口日记**：连续 7 天，每晚记录 1–3 个"缺口和异常"（不许写成点子），第 8 天把它们按 Drucker 七个来源分类，挑出一个让你最烦的写机会卡片。
3. **过滤器诊断**：列出你曾经想过、但因为"太麻烦"或"太不性感"而放弃的 2 个点子。按 Graham 的说法，哪个过滤器更可能是错觉？重新评估其中一个。
4. **辨析题**：Graham 说"竞争对手几乎可以忽略"，Andreessen 说"市场最重要"。这两个观点如何同时成立？（提示：拥挤市场 = 有需求的证据）
5. **加约束（Buchheit 法）**：选一个你最不确定的点子，在还没做出任何东西之前，48 小时内尝试"卖"给 5 个人（预售、预约或者至少要到付费意向）。记录他们拒绝的原因，看看过程中有没有冒出更好的点子。
