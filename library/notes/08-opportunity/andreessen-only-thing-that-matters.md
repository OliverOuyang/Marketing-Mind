# The only thing that matters（唯一重要的事）

> 来源说明：Andreessen 2007 年的博客早已下线，现由 Fictive Kin 维护的静态存档 pmarchive.com 免费提供，已转文本存私有目录。全文约 2,100 词，下文按论证顺序（定义 → 论点 → 三个追问 → PMF）定位。

## 一句话

决定创业成败的三要素（团队、产品、市场）里，**市场最重要**；所以对创业公司来说，**唯一重要的事是达到产品—市场契合（product/market fit）**：处在一个好市场里，有一个能满足这个市场的产品。

## 核心论点

1. **先定义三要素**（定义部分）：
   - **团队质量**：CEO、高管、工程师等关键人员相对于眼前机会的**适配度**，看的是能不能执行，而不是有没有"做过"；
   - **产品质量**：对**一个**真正使用它的客户来说有多出色（易用、功能、速度、可扩展、精致、bug 少）；
   - **市场规模**：这个产品的客户数量和**增长率**。
   （前提：能规模化赚钱，即获客成本不高于客户带来的收入。）
   他特别回应了反对意见："没人要的产品能有多好？"他的回答是：产品质量和市场规模完全不同。例子是"给一个没人用的操作系统做的世界最好的软件"（BeOS、Amiga、OS/2、NeXT）。
2. **为什么大家说团队或产品最重要**：创业者和 VC 常说团队，因为一开始你对团队的了解远多于对还没做出来的产品、还没探索过的市场；而且"人是最重要的资产"在美国文化里听起来很对。工程师常说产品，因为"没有产品就没有公司"。
3. **Andreessen 的立场：市场最重要**（论点部分）：在好市场里，**市场会把产品从创业公司里"拉"出来**。市场需要被满足，而且会被第一个可行的产品满足；产品不必很好，只要基本能用；市场不在乎团队有多好，只要团队能做出那个可行的产品。"客户在敲你的门……主要任务是接电话、回复所有想买的人的邮件。"好市场里，团队还很容易边跑边升级。例子：搜索关键词广告、互联网拍卖、TCP/IP 路由器。反过来，在糟糕的市场里，最好的产品加最强的团队也会失败，例子是视频会议、工作流软件、小额支付。
4. **Rachleff 定律**（纪念 Benchmark 的 Andy Rachleff）："创业公司的头号杀手是缺乏市场。"
   - 好团队遇到烂市场，市场赢；
   - 烂团队遇到好市场，市场赢；
   - 好团队遇到好市场，奇迹发生。
5. **三个追问**：
   - **好团队能带来什么？** 希望至少是一个还行的产品，但"伟大的产品真的、真的很难做"；也希望能找到好市场，但"不存在的市场不在乎你有多聪明"。最常见的"好团队 + 烂产品或烂市场"，是第一家公司大获成功的二次、三次创业者：他们会自负、失手。他举了一位当时正在烧约 8,000 万美元风投、却几乎只有媒体报道和几个 beta 客户的知名创业者（没有点名）。
   - **伟大的产品能创造新市场吗？** 能，但这是最好的情况，例子是 VMware。"除此之外，我不会指望你的产品从零创造一个新市场。"
   - **创始人该怎么做？** 见下一条。
6. **Rachleff 推论：唯一重要的事是达到 PMF**。PMF 就是"处在一个好市场里，有一个能满足这个市场的产品"。
   - **没有 PMF 时的感觉**：客户没从产品里得到足够价值，口碑不传播，使用增长不快，媒体评价"平平"，销售周期太长，很多单子谈不成。
   - **有 PMF 时的感觉**：客户买得和你做得一样快，使用量增长得和你加服务器一样快；客户的钱堆在公司账户里；你拼命招销售和客服；记者打电话来；你开始拿"年度企业家"奖；投行在你家门口蹲守……
7. **把创业分成 PMF 之前和之后**：PMF 之前（BPMF）要"痴迷地专注于达到 PMF"，做任何必要的事：换人、重写产品、换市场、对客户说"不"或说"是"、甚至融一轮高稀释的钱。"你可以忽略几乎所有别的事。"成功的公司往往在渠道、营销计划、公关、薪酬政策等方面都搞砸过，仍然成功；而很多运营井井有条、福利优厚、董事会豪华的公司"径直冲下悬崖"，因为从没找到 PMF。人们很不擅长理解因果：成功后创始人会把成功归因于各种无关的事，"但几乎每个案例里，原因其实是 PMF"。

## 框架 / 模型

### A. 团队 × 市场 2×2（Rachleff 定律）

| | 好市场 | 烂市场 |
|---|---|---|
| 好团队 | 奇迹发生 | 市场赢（失败） |
| 烂团队 | 市场赢（往往成功） | 失败 |

### B. PMF 信号清单（原文的"感觉"改成可观察指标）

| 没有 PMF | 有 PMF |
|---|---|
| 客户价值感不足 | 客户买得和你做得一样快 |
| 口碑不传播 | 使用增长快到基础设施跟不上 |
| 使用增长慢 | 收入在累积 |
| 媒体评价"平平" | 招人（销售、客服）赶不上需求 |
| 销售周期长、很多单谈不成 | 记者、投资人主动找上门 |

### C. 三要素的定义（便于诊断）

团队 = 对机会的适配度；产品 = 对**一个**用户有多好；市场 = 客户**数量 × 增长率**。

## 案例与数据

- **好市场拉动的例子**：搜索关键词广告、互联网拍卖、TCP/IP 路由器。
- **烂市场的例子**：视频会议、工作流软件、小额支付（注意这是 2007 年的判断，见边界第 3 条）。
- **产品好但市场不存在**：BeOS、Amiga、OS/2、NeXT 上的应用。
- **产品创造市场**：VMware 掀起操作系统虚拟化浪潮。
- **反面例子**：一位知名的连续创业者烧了约 8,000 万美元风投，只换来媒体报道和几个 beta 客户，原因是"他做的东西几乎没有市场"。
- **Tim Shephard**："伟大的团队是在同样的市场和产品下，总能打败平庸团队的团队。"

## 适用边界与常见误用

1. **"市场最重要"不是"团队不重要"**：Andreessen 明说他不是让你在团队质量上将就。他的意思是，团队无法拯救一个不存在的市场。
2. **对个人的迁移**：把"产品"换成"你的技能或作品"，把"市场"换成"谁需要、需要多迫切、人数在不在增长"。一个人在一个萎缩的领域里能力再强，也会很辛苦（可对照 Naval"把社会想要但还不知道怎么得到的东西给它"）。
3. **时代性**：他 2007 年列的"烂市场"（视频会议、小额支付）后来都出现了大公司（Zoom、各类移动支付）。这恰好说明市场会因为技术和环境变化而从"烂"变"好"。可以和 Drucker 的"产业结构变化""新知识"结合讨论：市场的好坏有**时机**维度。
4. **PMF 描述是"感觉"，不是指标**：原文写的是"你总能感觉到"。教学时要把它转成可观察的信号（留存、自然增长、付费转化、"如果不能再用会多失望"之类的调查）。原文本身没有给出量化门槛，不要编造。
5. **"可以忽略几乎所有别的事"**：前提是还在 PMF 之前。PMF 之后，渠道、团队、流程就变得重要（原文末尾编者按也承认这篇"提出的问题比回答的多"）。

## 出题素材

1. **Oliver 真实场景，三要素诊断**：用团队（Oliver 自己对这个机会的适配度）、产品（research-crawler 对一个真实用户有多好）、市场（需要调研抓取的人数和增长率）三项，各打 1–5 分并给出证据。哪一项最薄弱？按 Andreessen 的观点，他应该优先补哪一项？你同意吗？
2. **辨析题**：Andreessen 说"市场最重要"，Paul Graham 说"选一口深而窄的井"，Kelly 说"1,000 个铁杆就够"。三者矛盾吗？对一个想做个人品牌的学生，"好市场"应该怎么定义？
3. **信号转化题**：把原文"没有 PMF 的感觉"里的 5 条，各改写成一个 Oliver 可以在两周内测出来的指标（例如"口碑不传播"→"新用户中由老用户推荐来的比例"）。
4. **复盘题**：举一个你知道的"好团队 + 烂市场"的项目（学校社团、比赛项目、朋友的创业），用 Rachleff 定律分析失败原因。如果重来，应该换市场还是换产品？
5. **加约束**：如果 Oliver 只能做一件事来判断 research-crawler 所在的市场好不好，而且不能写代码，他会做什么？（提示：去卖、看对方愿不愿意付钱，接 Sarasvathy 和 Graham 注释 [15]）
