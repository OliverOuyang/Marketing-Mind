# Write Simply（写得简单）

> 资料说明：Paul Graham 个人网站上的免费短文（2021 年 3 月），全文约 600 词，不分小节。本笔记依据原文全文写成，按段落顺序用 ¶1–¶12 标注位置（¶1 = "I try to write using ordinary words…"，¶12 = 最后一段讲他的写作方式）。文章没有分节标题，下面的"框架"是笔记整理的，不是原文结构。
>
> 本库已有 Graham 的《How to Write Usefully》（附《Writing, Briefly》）笔记，讲"写什么才有用"；这篇只讲一件事：**为什么要用平常的词和简单的句子**。两篇配合着读。

## 30 秒读懂

- **一句话**：用平常的词、简单的句子写，读者省下读字的力气，才有力气想你的观点，也更可能读到最后。
- **举个例子**：同样介绍一个小工具，"本项目致力于为用户提供高效便捷的数据采集解决方案"不如"它帮你一晚上抓完 500 篇论文的摘要"（示例）。后一句读者不用费力解码，注意力全在"500 篇""一晚上"上。
- **什么时候用**：改稿时，发现自己在用"显得专业"的词或长句，就拿这篇当理由把它改掉。
- **可信度**：一手。依据作者官网原文全文；文章是个人经验论证，没有实验数据。

## 核心论点

1. **读得越省力，读者越投入，也读得越远**（¶1–¶2）。读者花在文字上的精力越少，留给观点的就越多。多数读者读到一半就没劲了；阅读的摩擦足够低，更多人会读到结尾。
2. **目标是 "saltintesta"：观点跳进脑子，读者几乎注意不到文字**（¶3–¶4）。他借意大利菜 saltimbocca（"跳进嘴里"）造了这个词。他也承认文字不可能是纯粹的观点，但对多数作者、多数时候，这就是该瞄准的方向。"大部分文章和纯粹观点之间的差距，填的不是诗意。"
3. **简单写更体贴**（¶5–¶6）。为了显得厉害而写得花哨，是让读者多干活来换你显得酷，"像拖着一条长裙摆让读者替你提着"。用英语写作时，很多读者不是母语者，他们对观点的理解可能远超对英语的理解，所以"话题难"不能成为"用词难"的理由。
4. **简单写让人诚实**（¶7）。花哨的文字不仅能掩盖观点，也能掩盖"没有观点"。简单地说空话，所有人（包括你自己）都会立刻看出来。
5. **简单的文字更耐久**（¶8–¶9）。未来的读者和今天的外国读者处境相似：文化和语言都变了。耐久不是虚荣，像木匠想让椅子结实一样，耐久是活干得好的标志。
6. **真正的原因：写复杂了让他难受**（¶10–¶11）。一句不必要的复杂句或知识分子腔的词，在他眼里不是高级，是笨拙。可以为了效果**故意**用复杂句或花哨词，"但永远不要无意中这么做"。
7. **方法：快写初稿，再花几天改，改的大部分是删**（¶12）。删让简单的文字更简单。这和《Writing, Briefly》《How to Write Usefully》里的 "loose, then tight" 是同一套流程。

## 框架 / 模型

**简单写的五个理由**（笔记整理，可做改稿时的提问卡）：

| 理由 | 原文位置 | 改稿时问自己 |
|---|---|---|
| 省力 → 更投入、读得更远 | ¶1–¶2 | 这句话读者要读两遍吗？ |
| 体贴读者（含非母语读者） | ¶5–¶6 | 我是在帮读者理解，还是在让自己显得厉害？ |
| 保持诚实 | ¶7 | 把这句话用最朴素的话重说一遍，还剩下什么观点？ |
| 耐久 | ¶8–¶9 | 三年后、换个圈子的人读，还看得懂吗？ |
| 复杂只能是故意的 | ¶11 | 这个难词、长句，是我选的，还是顺手写出来的？ |

**"最朴素重说"测试**（对应 ¶7）：把一段文案用对 12 岁小孩说话的方式重说一遍。如果重说后什么都不剩，问题不在措辞，而在没有观点。这时候该回去想内容，而不是继续润色。

## 案例与数据

- 本文没有实验或数据，是作者的经验论证。可用作教学的具体材料：
  - "saltintesta" 这个自造词和 saltimbocca 的类比（¶3）。
  - "拖着长裙摆让读者提着"的比喻（¶5）。
  - 文章本身就是示范：全文几乎没有一个难词，句子大多很短。可以让学生统计一下全文最长的句子有多长，作为"简单写"的样本。
- 相关的一手数据可以看本库其他笔记：Ogilvy 关于标题和正文阅读率的说法、Berger & Milkman 关于内容分享的实证研究。

## 适用边界与常见误用

- **简单 ≠ 浅**。PG 说的是措辞简单，不是观点简单。Julian Shapiro 的说法可以补充：用十三岁孩子能跟上的句子，表达任意复杂的观点。
- **简单 ≠ 口水话**。删掉大词以后，如果留下的是"其实""就是说""某种程度上"这类填充词，并没有更简单，只是换了一种啰嗦。
- **术语不是大词**。面向专业读者时，精确的术语（Positioning、JTBD、API）就是最简单的说法，强行换成大白话反而失真。判断标准是：目标读者在日常交流中会不会这么说。
- **"故意的复杂"要有理由**（¶11）。标题里用一个反常的词制造停顿，是故意；正文里堆"赋能""抓手"，是无意。
- **这篇只回答"怎么说"**，不回答"说什么"。观点本身弱，写得再简单也只是让弱点更明显（¶7 正是这个意思）。

## 出题素材

1. **（Oliver 真实场景：独立开发者发布长文）**Oliver 为自己的小游戏写发布长文。先写完初稿，然后逐句用"复杂只能是故意的"检查：每个难词、每个超过 25 个字的句子，标注"故意"还是"顺手"。顺手的全部改掉。追问：改完以后，文章变短了多少？哪一句的观点在改写后反而变弱了，为什么？
2. **最朴素重说**：把 Marketing-Mind 仓库 README 的第一段，用对 12 岁表弟说话的方式口头重说一遍并录音转文字。对比原文，哪些词在口头版里消失了？它们原本有用吗？
3. **非母语读者测试**：Oliver 的项目如果要发到英文社区（Hacker News、Reddit），找一个英语非母语的同学读英文版简介，请他圈出读了两遍的地方。
4. **诚实测试**：拿一条"看起来很专业"的产品介绍（自己的或别人的），删掉所有形容词和大词，看还剩下什么具体主张。剩下的如果是空的，这条介绍该重写的是内容。
5. **加难度**：用不超过 100 个汉字向一个不玩游戏的人介绍这款游戏为什么值得试，不许用"沉浸""体验""玩法"三个词。
