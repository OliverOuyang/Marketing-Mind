# Hacking Growth（增长黑客）

> 来源说明：这本书受版权保护，本笔记只整理框架，按**章节主题**标注，不写页码。全书分两部分：
> - Part I 讲方法：组建增长团队、判断产品是否 must-have、找增长杠杆和 North Star、高频测试。
> - Part II 按漏斗讲打法：获客、激活、留存、变现、良性循环。
>
> 书中的公司案例数字大多是作者转述，**本笔记不复述具体百分比**，只记打法。引用数字前请回原书核对。
>
> Sean Ellis 是 "growth hacker" 一词的提出者（2010 年），曾负责 Dropbox、LogMeIn、Eventbrite 早期的增长。

## 30 秒读懂

- **一句话**：增长靠的不是某个绝招，而是一套固定流程：先确认产品是用户离不开的，再选一个最能代表用户价值的核心指标，然后每周不断做小实验。
- **举个例子**：Sean Ellis 测试只问一个问题："如果再也不能用这个产品，你会有多失望？"超过 40% 的用户选"非常失望"，才说明产品已经站稳（判断 must-have 的章节）。你的小游戏如果只有 10% 的试玩者这么回答，就该先改游戏，而不是花钱拉人（示例）。
- **什么时候用**：产品已经有一些用户、想系统地提高增长，或者需要给一堆增长点子排优先级时。
- **可信度**：二手。版权书，未读原书；依据对全书框架的掌握，书中各公司的具体数字一律没有复述，细节以原书为准。

## 核心论点

1. **先 must-have，再增长**（Part I，判断 must-have 的章节）。在产品还不是"必需品"时加速获客，只会更快地烧钱。判断方法是 **Sean Ellis 测试**：问用户"如果再也不能用这个产品，你会有多失望？"如果有 **≥ 40%** 的用户回答 "very disappointed"，产品大概率已经 must-have。
   - 本库 01 模块的 Superhuman PMF Engine（Rahul Vohra）就是在这个测试的基础上发展出来的。
2. **找到 aha moment**（Part I / 激活相关章节）。aha moment 是用户第一次真正体会到产品核心价值的时刻。增长的第一要务，是让更多新用户**更快**到达这个时刻。
3. **North Star Metric**（找增长杠杆的章节）。选一个最能反映"用户获得了核心价值"的指标，让全公司对齐。书中常见的例子：Airbnb 看"预订晚数"，Facebook 看日活，WhatsApp 看发送的消息数。还要写出**增长方程**，把 North Star 拆成几个可以撬动的因子。
4. **增长团队是跨职能的**（组建团队的章节）。增长负责人、产品经理、工程师、数据分析师、设计师、营销一起工作，打破"营销负责拉新、产品负责功能"的部门墙。
5. **高频测试循环**（高频测试的章节）：
   - **Analyze**：看数据和用户行为，找机会。
   - **Ideate**：任何人都可以提实验点子，放进 backlog。
   - **Prioritize**：用 **ICE 打分**，即 Impact（影响）、Confidence（信心）、Ease（容易度），每项 1–10 分。
   - **Test**：跑实验，记录结果，学到的东西回流到下一轮。
   - **节奏本身就是杠杆**：每周的实验次数决定了学习速度。
6. **全漏斗都是增长的地方**（Part II）。获客、激活、留存、变现每一层都有打法，**留存是增长的地基**，留存不住，获客就是往漏桶里倒水。最终目标是形成良性循环（virtuous cycle）。

## 框架 / 模型

**增长黑客循环**：

```
   ┌──────────► Analyze（数据 + 用户行为）
   │                 │
 Learn               ▼
   │            Ideate（人人可提，进 backlog）
   │                 │
   │                 ▼
   └── Test ◄── Prioritize（ICE：Impact × Confidence × Ease）
```

**ICE 打分表**（可以直接用于 05 练习 2，为实验排序）：

| 实验点子 | Impact (1–10) | Confidence (1–10) | Ease (1–10) | ICE 平均 |
|---|---|---|---|---|
| | | | | |

**Sean Ellis 测试问卷**（must-have 判断）：
- "How would you feel if you could no longer use [product]?"
  - Very disappointed / Somewhat disappointed / Not disappointed / N/A（已不再使用）
- 阈值：very disappointed 的比例 ≥ 40%。

**AARRR 和本书 Part II 的对应**：Acquisition → Activation → Retention → Monetization（相当于 Revenue）→ Virtuous cycle（相当于 Referral 加上循环）。可以和 McClure 的海盗指标对照阅读。

## 案例与数据

（只列打法，不列书中数字）
- **Dropbox 的双向推荐奖励**：邀请人和被邀请人都获得额外存储空间。奖励本身就是产品的核心价值，这是 product-channel fit 的典范，也和 McClure 的 "refer after happy" 原则一致。
- **Facebook 的激活**：增长团队发现，新用户在早期加到一定数量的好友，和留存高度相关。于是 onboarding 的重点变成"帮新用户尽快加好友"。这是"找到 aha moment 然后缩短到达路径"的经典案例。
- **GrowthHackers.com**（作者自己的社区）：增长停滞时，提高每周实验的次数，重新找到了增长。这是"节奏是杠杆"的现身说法。
- **Airbnb 的 North Star 是预订晚数**：它同时反映了房东侧和房客侧的价值。

## 适用边界与常见误用

- **"Growth hacking" 被滥用成"找漏洞、刷数据、黑科技"**。书的本意恰恰相反：是**流程和纪律**，不是技巧。
- **40% 阈值是经验值，不是统计定律**。样本少于约 30–40 人时波动很大，而且必须问**真正用过产品的人**。
- **高频测试需要流量**。学生项目每周只有几十个访问，做 A/B 测试没有统计意义。这时应该用"定性 + 大改动"的实验，比如换一个完全不同的 onboarding，再看 5 个用户怎么用。
- **North Star 选错了，团队会被带偏**。例如选"注册数"，就会鼓励刷注册而不是创造价值。North Star 应该反映**用户获得的价值**，而不是公司想要的结果。
- **偏向 B2C 和 PLG 产品**。企业销售驱动的公司要做调整。
