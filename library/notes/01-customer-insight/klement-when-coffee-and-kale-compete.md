## 一句话

Job 不是"一项任务/活动"，而是**一个人想把现在的生活处境变成更好的处境、却被约束卡住时经历的过程**——人们买的是"一个更好的我"（a better me），所以功能毫不相干的东西（咖啡和羽衣甘蓝）也会彼此竞争。

## 核心论点

1. **Job 的定义（Klement 版）**："A Job to be Done is the process a consumer goes through whenever she aims to change her existing life-situation into a preferred one, but cannot because there are constraints that stop her."（"What is JTBD"）检验句："How are you better since you started using [product]?"
2. **Job 是被"设计"出来的，不是被发现的。** 例：Revlon 1952 年 "Fire and Ice" 广告几乎不提产品，一整页是挑衅式问题清单（"Have you ever wanted to wear an ankle bracelet?"），另一页是模特 Dorian Leigh——帮顾客想象"新的我"。Revson："In the factory we make cosmetics; in the drugstore we sell hope."
3. **最大的误用：把 job 当成活动或任务。** "store and retrieve music""listen to music"不是 job——Spotify 和 Pandora 恰恰是为了让人**不必**"存取音乐"而设计的；"听音乐"在健身房保持动力和去歌剧院是完全不同的事。
4. **不要把 job 分成功能/情感/社会三类。** 实践上：每个 job 都是核心情感欲望（归属、自我表达、控制……）的独特组合；理论上：job 是"设计问题"，不可证伪，没有客观测试能判定"这是社会型 job"。而且"功能/情感/社会"这个分类**只源自 Christensen 2003 年《The Innovator's Solution》里的一句话**，没有证据或引用（"Two Interpretations"）。——这与 HBR 2016 和本仓库模块 README 的"三层面"框架**正面冲突**，是很好的思辨材料。
5. **JTBD 有两个互不兼容的流派**（"Two Interpretations"）：
   - **Jobs-As-Progress**（Christensen、Moesta、Klement）：人买东西是为了**改变**（实现"Be goal"），理想状态是根本不必"做事"。
   - **Jobs-As-Activities**（Ulwick 及其 ODI 授权方）：job 是"任务、目标或要解决的问题"，以"核心功能性 job"为锚，用 Job Map（define, locate, prepare, confirm, execute, monitor, modify, conclude）分析；与 HCI、任务分析、Don Norman 的"行动七阶段"高度相似——这也是很多人批评"JTBD 不新鲜"的原因。
6. **Be goal > Do goal > Motor goal**（借 William Powers 的目标层级，Carver 2001）：高层 Be 目标（成为体贴的家人、感到安全）最稳定、纯情感；Do/Motor 目标是功能性的、依赖技术、可替换。"你搞砸了做晚饭，但家人仍觉得你很体贴"→ Be 目标照样达成；反之菜做得完美，家人想去餐厅，也算失败。
7. **竞争由 Be 目标定义，跨越功能。** Clarity（Dan Martell 的专家咨询平台）的客户想"被激励、被启发"，在"参加会议"和"与名人视频通话"之间权衡——功能完全不同，却在竞争同一个 job。IKEA 让你不必"钻四分之一英寸的洞"，2017 年又收购 TaskRabbit，因为人们连"组装家具"也不想做。割草：自动割草机、草坪服务、人工草皮都在帮人**不必割草**。

## 框架 / 模型

### A. 判断"这是不是一个 Customer Job"的问句

- 这句描述的是"更好的我"吗？还是在描述一个活动、一个任务、一个功能？
- 把产品去掉，这句话是否仍然成立？
- 它回答了"你用了之后，在哪方面变得更好了？"吗？

### B. Job Story 模板（来自 Intercom，Klement 命名并推广）

> **When** ___（情境/触发事件）, **I want to** ___（动机）, **so I can** ___（预期结果）.

对比 User Story："As a [type of user], I want [some action], so that [outcome]"——问题是从 persona 出发、预设了动作、"doesn't acknowledge causality"。练习：把"As a ___"整段删掉，"Did the sky fall?"

- Intercom 原例："When an important new customer signs up, I want to be notified, so I can start a conversation with them."
- 改写例：User Story "As an estimator, I want to see the item we're estimating, so that I know what I'm giving an estimate for." → Job Story "When I find an item I want to set an estimate for, I want to be able to see it, so that I can confirm that the item I'm estimating is actually the correct one."
- 进阶（2014 更新）：把"Motivations"改成"Motivations and Forces"——在 When 子句里写进焦虑（eBay 例："When a Buyer has already made a bid on an item, they are anxious about missing a counter bid…"）。
- 多角色时可在 When 子句里写角色；事件影响所有人时用 "customer / someone"，**不要用 "user"**（"lifeless and sterile"）。
- 原则："Define Motivations, Don't Define Implementation."

> 注：本仓库模块 README 的"JTBD 任务陈述公式"（当___时，我想要___，以便___）就是 Job Story 格式。

### C. 两个流派对照表

| 维度 | Jobs-As-Progress | Jobs-As-Activities（Ulwick/ODI） |
|---|---|---|
| 人为什么买 | 想改变处境、成为更好的自己 | 想更好/更快/更便宜地完成某项任务 |
| 分析单位 | 未达成的 Be goal、切换行为 | 核心功能性 job + Job Map + desired outcome |
| 情感的位置 | 核心 | 围绕核心功能 job 的附属 |
| 创新方向 | 常常是**消除**任务（割草例） | 优化任务执行 |
| 研究方法 | 切换访谈、四力 | 大样本 outcome 问卷、重要度×满意度 |
| 典型例子 | Revlon"卖希望" | "四分之一英寸的洞" |

### D. 书的整体结构（基于对该书的了解）

原则篇：Customer Job 的定义与原则（人们想要进步而非产品；job 稳定而方案会变；竞争由 job 定义；创新常常是让旧习惯被新习惯替代）→ 力量篇：推动需求与阻碍需求的力（与 Moesta 四力同源，Klement 用"demand generating / demand reducing"的思路组织）→ 方法篇：访谈与 Job Story → 案例篇（Clarity、Basecamp 等）→ 系统与组织篇（Deming 系统思维）。

## 案例与数据

- **Andreas 与 Basecamp**（"What is JTBD"）：做医疗旅游、5 名员工，用 Google Sheets/Docs + 邮件管公司，以为"公司就到头了"；朋友 Jamie 在咖啡店提到 Basecamp，"helped small businesses become better at organizing themselves"；回家的火车上他查了 Basecamp 和同类产品 → 注册 → **公司第一次超过 5 人**。Job：从"到顶的小作坊"变成"能继续长大的公司"。
- **Revlon "Fire and Ice"（1952）**：产品只在页面底部出现。
- **送手表**：Klement 送合伙人一块表表达感谢——"How can my JTBD be functional if I never directly use it?"
- **Clarity**：顾客的 Be goal 是"被激励、被启发"，竞争者从会议到名人视频通话（"Two Interpretations"，书中有完整案例章）。
- **IKEA + TaskRabbit（2017）、割草三种替代**：见核心论点 7。
- **Deming 名言**（作者引用）："A dissatisfied customer does not complain; he just switches."；真空管 vs 晶体管收音机。

## 适用边界与常见误用

1. **Klement 自己承认 Jobs-As-Progress"is a theory only… descriptive, not prescriptive"**——它解释为什么人切换，不直接告诉你做什么；要配合方法（访谈、Job Story）。
2. **"不要分类型"和 Christensen/模块 README 的"三层面"冲突**：导师的立场建议——"三层面"可作为**提问清单**（帮你别漏掉情感和社会因素），但不要把 job **归类**成某一型、更不要为分类争论。这正是"用框架但不迷信框架"的现场示范。
3. **"新的我"写得太空**：学生容易写成"成为更好的人"。必须带处境和约束（Andreas：5 人、用 Google Sheets、以为到顶了）。
4. **Job Story 的 When 子句最常写错**：写成人群（"When I am a student"）而不是情境/触发事件（"When I'm ready to have estimators bid on my game"）。
5. **流派之争有利益背景**：Klement 与 Ulwick 都是咨询从业者，ODI 是专利方法——阅读双方观点时注意立场。
6. **Be goal 理论的学术基础**来自控制论/自我调节心理学（Powers、Carver），Klement 将其迁移到市场是他自己的推论，未经实证检验。

## 出题素材

1. **（Oliver 真实场景）为 research-crawler 写 3 条 Job Story**：严格用 "When ___, I want to ___, so I can ___"，When 必须是**触发事件**；至少一条把焦虑写进 When（Motivations and Forces）。然后各写一句"用户用了之后在哪方面变成更好的自己？"
2. **（Oliver 真实场景）你的"咖啡与羽衣甘蓝"**：一个想"在暑假做出让招聘方眼前一亮的作品"的同学，可能在 research-crawler、Kaggle 比赛、实验室 RA、做一个小红书账号之间犹豫。列出 4 个功能毫不相干的竞争者，说明它们竞争的是哪个 Be goal。
3. **改写 User Story**：把三条"As a ___, I want ___, so that ___"改写成 Job Story（导师现场给题，例如"As a student, I want to export my research results as CSV, so that I can analyze them"）。
4. **思辨题**：Klement 说"功能/情感/社会"分类是"一句话、没证据"的流行说法；HBR 2016 说"Jobs are never simply about function"。两者真的矛盾吗？写 100 字的你的立场。
5. **割草测试**：找一件你每周都在"做"、但其实不想做的事（例：手动整理调研笔记），用"消除任务"的思路设计 3 种让它消失的方案（不一定是软件）。
