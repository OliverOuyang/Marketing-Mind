# 写作模式

先过 SKILL.md 的"动笔前先挖素材"，写完过"五个检验"。下面是各体裁的结构。参照例句来自仓库里拆过的真实案例，只借结构，不借原句。

## 发布帖（X、小红书、Product Hunt、朋友圈、即刻）

7 个零件，英文约 120 词以内，中文约 200 字以内：

1. 反问或反转式开头，重新定义类别（参照结构："The best AI recording hardware? You may already own it."）
2. 一句话说清它是什么
3. 一个替代方案没有的东西
4. 一句具体、可验证的拆顾虑句
5. 报价或使用门槛（免费、开源、限时、一次买断）
6. 一个让人想评论的问题，问题本身帮读者想象使用场景
7. 行动链接 + 一份可转发素材（视频、截图、示例结果）

交付时给 2–3 个不同角度的开头，正文给一版完整稿。

## 作品发布帖（小游戏、Demo、视觉作品）

能直接打开、靠"好看"传播的作品，用更短的 6 零件版，100 字以内，讲故事交给视频和转发者（案例：Sac《小王子：星辰之旅》，见 [Sac 镜头](../lenses/sac.md)）：

1. 具体数字（做了几天、几个关卡、几种语言）
2. 熟悉的 IP 或场景：读者不用解释就有情绪
3. 公开方法：点名用到的工具
4. 低姿态求支持
5. 下一波预告（开源、教程、新版本），写了日期就必须兑现
6. 可直接打开的入口 + 一段视频

动笔前先做**选题情绪测试**：不认识作者的人看到标题，会想起什么？挂在公共记忆（名著、童年、共同经历）上的选题，转发者不用解释。

交付时附一份**首小时转发名单**草稿：3–5 个首批转发者，各自为什么会转。帖子里点名的工具和人都是潜在转发者，检查"被点名的人有没有理由转"。没有名单就先别急着发。

面向同行时，准备好第二篇：**手把手教程**，开头用第一波的数字做社会证明，正文给可复用的提示词或步骤，并写明哪些是人的判断（"由我确认""反复调试出的"）。借作品信用推荐产品时标明赞助。

## 长文 / 复盘文（公众号、知乎、X Article、博客）

1. **标题**：时间 + 数字 + 具体结果 + 一个大判断或时代叙事；大判断适度降调（"我可能"）。给 3 个备选，说明各自打的是哪种好奇心。
2. **目录预告**：开篇列出 4–6 部分，让读者知道能拿走什么。
3. **开头**：先给结果或落差，再回到低点（当时的焦虑、被质疑、差点放弃）。
4. **社会证明**：截图、数据、别人的原话，不写"很多人喜欢"。标出每处要补的截图。
5. **起源**：自己就是用户；痛点逐条写具体；一个顿悟时刻；一个"为什么是现在"的外部信号。
6. **产品部分**：每个设计写成"我为什么这样取舍"，至少一处说出代价。
7. **具体场景**：用一个具体的人或一天代替抽象的"提升效率"。
8. **预先回应质疑**：把最可能被质疑的点写进故事。
9. **经验部分**：把可复用的方法"开源"出来，给读者带得走的东西。
10. **收口**：感谢具体的人和社区；引向一个具体下一步。

**没有大结果时**（踩坑复盘、实测文、刚起步的项目）：

- 用实测数字代替战绩：状态码、成功率、花费、条数、天数。估算写"估算"。
- 低点更要具体：哪一晚、哪一步、报错原文。踩坑本身就是故事。
- 价值落在"带得走的东西"上：清单、对比表、避坑原则，最容易被收藏。
- 大判断只用一次，并用"可能"降调；没有硬结果撑着时，观点型标题只放在知乎这类接受观点的平台。
- 结果太薄的过程类内容（公开学习、从零开始）定位成系列第 1 期，结尾预告下一期。

语气：口语化、带真实情绪、对趋势判断笃定、对自己的成绩往下压、会自嘲；下结论前可以先"叠个甲"，先给体面说法再给大白话。用用户自己的词。

## 把功能翻成情绪（长文、发布帖、视频通用）

大多数功能别人也想得到，差别在怎么讲。

1. **价值阶梯**：每个主打功能写满三层：功能（是什么）→ 好处（能帮你做什么）→ 情绪（让你感觉怎样）。参照结构："原音回放"→"能再听见那一天"→"重新回到过去的一天，而不是只剩一份摘要"。
2. **小功能写成偶然发现**：不写"支持 X"，写"有一次……偶然发现……居然……"。必须是用户真实经历过的，没有就留 `【待补】`。
3. **关系化语言**：用"你"做主语，写陪伴、积累、越用越懂；配一个具体的人和场景。
4. **熟悉的界面做证据**：朋友圈、聊天、推文、榜单、通知这些读者天天见的原生截图，比自己做的宣传图更有真实感。
5. **情绪曲线**：开发过程按"开心 → 紧张 → 焦虑 → 冲刺 → 结果"写，每段一个具体时刻；"开发用时"和"销售天数"不要混成一个数。
6. **站进热门类别**：点名 2–4 个同类产品或趋势词，再说自己在这个类别里占哪个位置。

底线：情绪只能放大真实存在的功能和体验。

## 按平台改说法

同一篇内容发到不同平台，标题和第一句要重写。中英双版也一样，中文版不是英文版的翻译。

- **公众号 / 知乎**：可以写结果和数字，长标题，带时代叙事。
- **小红书**：少提钱，多提"你也可以"和可见的成果（榜单、截图、曲线）；标题偏邀请式（"来把你的 X 变成 Y"）。
- **X / Product Hunt**：英文短句，反问开头，we 视角，顾虑和报价一行一句。
- **GitHub README 首屏**：一句话是什么 + 一张动图或截图 + 一个三步内能跑起来的上手方式 + 一个可验证的亮点。
- **Steam 商店页 / 游戏发布**：前几秒的画面就是钩子；先让玩家看到"玩起来是什么样"，再讲背景。

## 小红书长文图卡

1. **封面**：一张数据图（增长曲线、榜单截图）或大标题；标"全文 N 字｜阅读需 N 分钟"；一段导语预告各部分，读者最想知道的（收入、结果）放最后。
2. **正文**：每张卡一个小节，小节标题短而有力；关键句单独成段。
3. **话题标签**：身份（个人开发者、大学生）+ 领域 + 情绪类标签。
4. **正文文字**：可以只放标签和一句引导，内容在图里。

## 自我介绍、简历亮点、作品集

- 套用定位五组件：先说替代方案（"没有我，他们会找谁"），再说独特属性和证据。
- 每条亮点写成"动作 + 可验证的结果 + 一个具体场景"，不写形容词。
- 电梯演讲结构见模块 06。

## 发布顺序（产品号和个人号分开发声时）

默认：产品号先发（只讲产品，结构见发布帖）→ 攒社会证明（榜单、数据、别人的测评）→ 个人号用长文"认领"→ 产品号转发长文 → 之后用更新日志持续发帖。
