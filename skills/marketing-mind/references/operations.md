# 运营模式

产出一份运营计划，包含七部分：

1. **账号定位**：一句话说清"这个号持续给谁什么"，窄切口 + 大口号各一句；个人号和产品号是否分开，理由是什么。
2. **素材库盘点**：现有可展示的作品、数据、过程记录，以及缺口。
3. **选题库**：至少 15 个，分三类，每个写一行标题草稿和对应素材：
   - 作品类：发布、更新日志、功能背后的取舍
   - 过程类：做东西的低点、踩坑、复盘（引爆点通常在这里）
   - 方法类：把经验"开源"给读者
4. **节奏**：两种打法选一种并说明理由。
   - **事件制**：只在发布、复盘、大版本更新时发，每条都是重磅（案例：BaiFu 的小红书一年只发 7 条）。
   - **日常制**：固定频率的小更新，加事件长文。
   无论哪种，都写清"阶段性结果出现就写复盘"的触发条件（Star、用户数、收入、wishlist、一次被拒）。
5. **渠道**：每个平台的角色（首发、长文、演示视频、社区讨论）。先选牛眼框架（模块 05）里最可能的 3 个渠道各做一张实验卡；先去社区自己发，不要等投稿被收。
6. **互动**：评论怎么回、用户反馈怎么写进更新日志、点名感谢谁。
7. **衡量**：每个阶段只看 1–2 个数字。小红书收藏数接近或超过点赞，说明内容有实用价值，这类选题要多做。

## 发布周日历（作品首发时）

首发只是第一天，每天给大家一个回到原帖的新理由（案例：Sac 小王子发布周）：

| 天 | 动作 | 目的 |
|---|---|---|
| D-1 | 预告并写明准点发布时间 | 让关注者等着 |
| D0 | 准点首发；首小时名单里的人接力转发 | 冲第一波 |
| D1 | 互动活动（转发原帖并晒截图抽奖）、多语言、开反馈帖集中收吐槽 | 把互动导回原帖 |
| D2 | 手把手教程，开头放第一波数字 | 方法即第二个产品，收藏通常高于点赞 |
| D3–D6 | 回复转发者、修 bug 发更新、预告下一波 | 续热度，兑现承诺 |

承诺（开源、更新）写了日期就要按时兑现；做不到就改成不带日期的说法。

## 常见场景的默认值

| 场景 | 默认节奏 | 主渠道 | 看什么数 |
|---|---|---|---|
| 开源项目 | 事件制：发布、里程碑复盘、大版本 | GitHub + X/即刻 + 一篇中文长文 | Star、issue 里的真实使用者 |
| 独立游戏 | 先营销再开发：商店页尽早上线，按开发进度公开练手；首发用发布周日历 | Steam 商店页 + 短视频 + Reddit/社区 | wishlist、试玩转化 |
| App / 小工具 | 产品号首发 + 创始人长文认领 + 更新日志 | X/小红书 + 商店页 | 下载、付费、留存 |
| 个人品牌 / 求职 | 日常制：公开学习 + 作品长文 | 小红书/知乎/LinkedIn + GitHub | 私信、面试邀请、合作 |

这些是起点，不是答案，按用户的作品和受众调整，并说明为什么。
